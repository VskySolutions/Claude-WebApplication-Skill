# Branding and theming: per-tenant themes applied at runtime

The app ships one stock look (the tokens in `foundations.md`) and lets each tenant override it with a
**sparse theme** plus five images, applied by an injected stylesheet before the first paint. Source:
`services/branding.js`, `stores/branding.js`, `boot/branding.js`, `boot/title.js`,
`modules/branding/*`, `layouts/*`.

## 1. The theme model

`DEFAULT_THEME` (frozen) restates `src/css` and is the single description of the stock look:

```js
identity:   { applicationName: "EMS Portal", tagline: null, footerText: null, supportEmail: null, supportUrl: null, logoHeight: 57, showNameBesideLogo: true }
colors:     { primary, secondary, accent, positive, negative, warning, info, pageBackground, surface, text, textMuted, border, link,
              headerBackground, headerText, sidebarBackground, sidebarText, sidebarActiveBackground, sidebarActiveText,
              tableHeaderBackground, tableHeaderText }          // hex strings
typography: { bodyFont: "Poppins", headingFont: "Poppins", baseFontSize: 15, headingColor: primary,
              h1..h6: { size, weight, lineHeight, letterSpacing, transform, color } }
buttons:    { radius: 3, uppercase: false, fontWeight: 500, primary: { background, text: "#ffffff", border }, secondary: { background, text, border } }
shape:      { cardRadius: 5, inputRadius: 4, cardShadow: "soft" | "none" | "raised" }
login:      { backgroundColor: "#f4f6fb", headline: "Welcome back 👋", subtext: "Please sign in to your account to continue." }
```

- A tenant's theme is **sparse**: `null` means "as the application ships". An untouched tenant emits no
  CSS at all. `emptyTheme()` is the editor's blank form (every key present, null); `toDraft(theme)` lays an
  API theme over it; `resolveTheme(theme)` lays it over the defaults **and** follows the derived settings:
  link → primary, sidebar active text → primary, sidebar active background → `tint(primary, .88)`, heading
  colour → primary, primary button background → primary, secondary button text → primary, secondary border
  → its text.
- Colour helpers: `isHex`, `mix`, `tint`, `shade`, `contrastRatio` (WCAG; body text wants ≥ 4.5).
- "Secondary button" means the outlined `color="primary"` button; the app has no `color="secondary"` buttons.

## 2. From theme to stylesheet

`buildCss(theme)` validates every value again (the theme is also read back from localStorage) and emits:

| Setting | What it writes |
|---|---|
| `colors.primary` | `--q-primary` and the whole teal ramp (`--teal-900` = shade 45% … `--teal-050` = tint 94%), plus `.bg-teal-1 { background: tint(primary, .88) !important }` |
| `colors.accent` | `--q-accent`, `--gold-600`, `--gold-100` |
| `secondary/positive/negative/warning/info` | the matching `--q-*` |
| `text` / `textMuted` / `border` | `--q-dark` + `--ink-900` / `--ink-500` / `--line` |
| `pageBackground`, `text`, `bodyFont`, `baseFontSize` | `body { … }` |
| `surface`, `cardRadius`, `cardShadow` | `.q-card { background; border-radius !important; box-shadow }`; `border` → `.q-card--bordered, .q-separator` |
| `inputRadius` | `.q-field--outlined .q-field__control { border-radius }` |
| `link` | `a:not([class*="q-"]) { color }` |
| header / sidebar / sidebar-active / table header colours | `.q-header.header`, `.q-drawer--left.bg-white`, `.app-menu .app-menu__active` (+ flyout), `.q-table thead th` |
| `headingFont`, `headingColor`, per-heading size/weight/lineHeight/letterSpacing/transform/color | `h1..h6, .text-h1..h6, .text-subtitle1, .text-subtitle2` |
| buttons | `.q-btn:not(.q-btn--round):not(.q-btn--fab) { border-radius }`, text-transform/weight, `.q-btn.bg-primary` background/text/border, `.q-btn.q-btn--outline.text-primary` background/text/border |

`applyBranding({ theme, assets })` writes the CSS into a `<style id="brand-theme">` appended **last** in
`<head>` (so equal-specificity rules beat the bundled stylesheets), loads the fonts, and swaps the favicon
links to the uploaded icon (restoring the stock ones when removed).

## 3. Fonts

- Every Google Fonts family is offered, grouped by category (sans-serif, serif, display, handwriting,
  monospace) after a "System default" entry; the catalogue `services/google-fonts.json` is generated by
  `scripts/update-google-fonts.mjs` (`nps google_fonts`) and must not be hand-edited.
- `fontStack(name)` returns `"Name", <category fallback>`; `ensureFonts(names)` appends one `<link>` per
  family (`fonts.googleapis.com/css?family=…:300,400,500,600,700,800&display=swap`, the v1 endpoint on purpose
  because css2 rejects a request when any weight is missing); Poppins, Merriweather and Roboto are already bundled.

## 4. Images (assets)

Five slots, each saved immediately on upload (not with Save), PNG/JPEG/WebP/ICO only (SVG refused):

| Slot | Where it shows | Guidance shown in the editor |
|---|---|---|
| `logo` | Side menu, sign-in screen | wide, transparent PNG about 400px wide, 2 MB |
| `logoDark` | Primary-coloured header of public forms (falls back to `logo`) | wide, 2 MB, previewed on the primary colour |
| `logoMark` | Alone in the collapsed menu rail | square ~128px, 2 MB |
| `favicon` | Browser tab | square PNG/ICO ≥ 32px, 2 MB |
| `loginBackground` | Behind the sign-in card (`cover`, centred) | wide, 5 MB |

`assetUrl(path)` prefixes the API base URL. Logo height in the menu is a theme setting (20–64px).

## 5. Lifecycle

- `boot/branding.js`: `hydrate()` from the browser `localStorage` cache (`branding`) before the first paint;
  `load()` when a token exists; reload on sign-in (null → token) and on `tenant-switched`; `keepCache()` on
  `session-cleared` so the next sign-in screen still wears the firm's look.
- Public screens: `/auth/login?tenant=<identifier>` loads a tenant's public branding for a browser that has
  never signed in; an invite link loads the sending firm's branding **without caching** (a member of staff
  opening a client's link must not have their own sign-in screen rebranded).
- `preview(theme, assets)` dresses the whole application in a draft (editor toggle "Try it on this
  application"); `endPreview()` restores the saved look; leaving the editor ends the preview.
- `boot/title.js` keeps `document.title` in step with the branded application name.

## 6. The branding editor UI

`BrandingEditor` (used on the Branding settings page and as a tab on the Tenant page, `tenantId` optional):
- Left `col-12 col-md-7`: a `q-card` with `q-tabs dense no-caps outside-arrows mobile-arrows` — Identity,
  Logos, Colours, Typography, Buttons, Shape, Sign-in screen — and `q-tab-panels animated keep-alive`.
  Footer `q-card-actions bg-grey-1`: "Reset to default" (flat negative, only when customised), spacer,
  "Discard changes" (flat grey-8, only when dirty), Save (primary, disabled unless dirty). A caption "Last
  changed <date> by <name>." under the card. Leaving with unsaved changes asks.
- Right `col-12 col-md-5`: a sticky (≥1024px, `top: 62px`) Preview card with the "Try it on this
  application" toggle and `BrandingPreview`.
- Field components: `BrandingColorField` (hex box with a swatch button that opens `q-color` on
  `q-popup-proxy`; the placeholder is the effective fallback colour; a dashed, faded swatch means "stock
  colour standing in"; `o_restart_alt` clears back to default; `#abc` expands to `#aabbcc`; leaving with a
  half colour restores the last good one), `BrandingNumberField` (number input with suffix, min/max/step
  clamped on blur, placeholder = default), `BrandingAssetSlot` (72px framed preview on a chosen backdrop,
  label, hint, Upload/Replace outlined + Remove flat negative, validation message).
- Colours tab opens with **presets** (Teal stock, Ocean, Forest, Burgundy, Indigo, Slate, Sunset) as outlined
  grey buttons with a 12px dot; then colour groups Brand / Status / Surfaces and text / Header and side menu
  / Tables under `.section-subhead`s, each field with an `info` tooltip.
- Typography tab: body/heading font selects (grouped, searchable), base size, heading colour, then an
  expansion list H1–H6 (`group="headings"`) each with size, weight (300–900), letter case, line height,
  letter spacing, colour; the header caption shows the effective `size · weight` and "customised".
- `BrandingPreview` draws a miniature shell (sidebar with an active item, header, page with a card holding
  H1–H6, body text, a field, primary/secondary buttons, status chips, a table) and the sign-in card, all
  from the resolved theme, plus a red contrast warning under the buttons when the primary button's text
  falls under 4.5:1.

## 7. Making a new app themeable

1. Keep every colour reference in components as a Quasar colour name or a `--q-*`/token variable; never a
   literal brand hex.
2. Keep the three places that define the stock look in step: `tokens.scss`, `quasar.variables.scss`,
   `DEFAULT_THEME`.
3. Give the shell the class hooks the stylesheet targets: `.q-header.header`, `.q-drawer--left.bg-white`,
   `.app-menu__active`, `.q-table thead th`, `.text-h*`/`.text-subtitle*`, `.q-btn.bg-primary`,
   `.q-btn.q-btn--outline.text-primary`.
4. Read `appName`, logos and the login copy from the branding store in layouts rather than hard-coding them.
